# Requirement Review Rules

## 1. Evidence Discipline

不得把推测当成需求事实。

每一个P0问题必须能够追溯到：

- 需求文本
- 核心业务逻辑
- 明确存在但未定义的规则

---

## 2. Priority

### P0

不确认将直接影响：

- 核心业务逻辑
- 状态机
- 权限模型
- 核心数据模型
- 核心流程闭环

### P1

影响：

- 交互
- 辅助流程
- 数据展示
- 非核心异常处理

### P2

后续可以确认的问题。

---

## 3. No Invented Scenarios

不得为了增加问题数量而创造需求中不存在的业务场景。

---

## 4. Read-only

评审过程中不得修改：

- 原始需求
- 项目规则
- 测试数据
